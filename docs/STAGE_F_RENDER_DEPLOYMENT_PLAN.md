## 3. SPA ROUTING & BROWSER REFRESH CONFIGURATION

### 3.1 The Single-Page Application (SPA) Challenge
In client-side routed applications (React Router v6), navigation to nested routes like `/:hospitalSlug/dashboard` or `/:hospitalSlug/prescriptions` is handled in browser memory. When a user bookmarks a page or refreshes their browser, the browser requests the raw path from the CDN web server. Without an explicit SPA fallback rule, the server returns an HTTP 404 (Not Found).

### 3.2 The Render `_redirects` Solution
Render Static Sites natively support Netlify-compatible `_redirects` files placed in the publish root (`dist`).

- **Source File:** `quroxa-patient-frontend/public/_redirects`
- **Rule Definition:**
  ```text
  /*    /index.html   200
  ```
- **Build Verification:**
  - Vite automatically copies all files from `public/` directly into `dist/` during the build step.
  - Verified on disk: `quroxa-patient-frontend/dist/_redirects` exists and contains the exact rule.
- **Routing Invariant:**
  - Any request that does NOT match a physical static asset (e.g. `.js`, `.css`, `.svg`, `.png`) is rewritten internally to `/index.html` with an HTTP 200 status.
  - React Router then takes over and mounts the correct view based on the URL path.

### 3.3 Tested Nested Routes Matrix
The following deep-link paths are verified to resolve cleanly on direct navigation and hard refresh:
- `/:hospitalSlug/login` (Authentication entry point)
- `/:hospitalSlug/dashboard` (Clinical overview)
- `/:hospitalSlug/appointments` (OPD consultation list)
- `/:hospitalSlug/appointments/book` (Doctor consultation booking)
- `/:hospitalSlug/prescriptions` (Digital prescriptions & letterhead)
- `/:hospitalSlug/lab-results` (Pathology diagnostic reports)
- `/:hospitalSlug/medical-records` (EMR encounters & discharge documents)
- `/:hospitalSlug/billing` (Read-only financial overview)
- `/:hospitalSlug/profile` (Demographics and account settings)
- `/:hospitalSlug/privacy` (DPDP Act 2023 statutory consent center)

## 4. ENVIRONMENT VARIABLE CONFIGURATION IN RENDER

Configure the following environment variables in the Render Dashboard under **Environment** for the new Static Site:

| Variable Key | Required | Example Production Value | Purpose & Architectural Contract |
|:---|:---:|:---|:---|
| `VITE_API_URL` | **Yes** | `https://api.quroxa.com/api` (or `https://quroxa-backend.onrender.com/api`) | Fully qualified base URL of the shared backend API. Must include `/api` suffix (client automatically appends if omitted). |
| `VITE_SOCKET_URL` | **Yes** | `https://api.quroxa.com` (or `https://quroxa-backend.onrender.com`) | Fully qualified base URL of the Socket.IO server. Must be the server root (WITHOUT `/api`). |

> **SECURITY RULE:** Do NOT configure `JWT_SECRET`, `MONGO_URI`, `PING4SMS_API_KEY`, or any private backend credentials in the Static Site environment. Vite variables prefixed with `VITE_` are embedded into the client-side JavaScript bundle and are completely public by design.

## 5. STEP-BY-STEP OPERATOR DEPLOYMENT GUIDE (FOR FUTURE EXECUTION)

> **NOTICE:** The following steps are documented for authorization and operator execution only. Do NOT execute these steps during Stage F.

### Step 1: Log in to Render Dashboard
1. Navigate to `https://dashboard.render.com`.
2. Select your team/organization workspace where the existing backend service is running.

### Step 2: Create New Static Site
1. Click **New +** in the top navigation and select **Static Site**.
2. Connect your Git provider and select the repository containing QUROXA.
3. Configure the service parameters:
   - **Name:** `quroxa-patient-frontend`
   - **Branch:** `master`
   - **Root Directory:** `quroxa-patient-frontend`
   - **Build Command:** `npm run build`
   - **Publish Directory:** `dist`

### Step 3: Configure Environment Variables
1. Under **Environment Variables**, click **Add Environment Variable**.
2. Key: `VITE_API_URL` -> Value: (Your backend API URL, e.g. `https://quroxa-backend.onrender.com/api`).
3. Key: `VITE_SOCKET_URL` -> Value: (Your backend host URL, e.g. `https://quroxa-backend.onrender.com`).
4. Click **Create Static Site**.

### Step 4: Validate Initial Build Logs
1. Render will clone the repository, navigate to `quroxa-patient-frontend`, run `npm install`, and execute `npm run build`.
2. Verify build log outputs:
   - `✓ 1600 modules transformed.`
   - `dist/index.html` generated.
   - `dist/_redirects` generated.
   - Status: `Site is live at https://quroxa-patient-frontend.onrender.com`.

## 6. CUSTOM DOMAIN & SSL CONFIGURATION

### 6.1 Planned Production Domain Structure
- **Production Patient Portal Domain:** e.g. `https://patient.quroxa.com` (or `https://portal.quroxa.com`)
- **Production Staff Portal Domain:** e.g. `https://app.quroxa.com` (existing)
- **Production Backend API Domain:** e.g. `https://api.quroxa.com` (existing)

### 6.2 DNS Record Configuration (Post-Approval)
In your DNS provider (Cloudflare, GoDaddy, AWS Route 53):
1. Create a `CNAME` record:
   - **Type:** `CNAME`
   - **Host / Name:** `patient` (or `portal`)
   - **Target / Value:** `quroxa-patient-frontend.onrender.com`
   - **TTL:** Auto or 300s
   - **Proxy Status:** DNS Only during initial SSL verification (if using Cloudflare).
2. In the Render Dashboard under **Settings -> Custom Domains**:
   - Add `patient.quroxa.com`.
   - Render automatically provisions a free Let's Encrypt SSL/TLS certificate.
   - Verify certificate status: `Active (HTTPS Enforced)`.
